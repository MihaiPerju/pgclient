What it does

Everything you open a database client for, and the things you usually open three other tools for.

It knows your schema while you type

When you pick a database, its tables, columns and foreign keys load once and stay. The editor suggests from them before you type the first letter.

  • After from or join: tables.
  • After an alias and a dot: that table's columns.
  • After join … on: the conditions your foreign keys give.

Find the session that is holding everyone up

The Sessions view shows who is connected, what they run, and for how long. A session idle in a transaction, keeping its locks, is flagged. So is the one waiting on it.

  • Blocking and waiting are called out in plain words, with the PID.
  • Cancel query or End session on the row.
  • Refreshes every two seconds.

A live dashboard, without a monitoring stack

Transactions per second, connections by state, rows in and out, WAL, and cache hits against disk reads. They are drawn from Postgres's own statistics over the connection you already have open.

A strip above the editor keeps connections, active sessions, blocked sessions, cache hit ratio and TPS in view while you work.

Read a plan in seconds

Explain shows how Postgres would run the query without running it. Each node is a bar sized by its cost, so the expensive step is the one that stands out. Click a node for its rows, filter and width.

Explain Analyze runs it for real times when you want them.

Built for working on real servers

Small details that keep you out of trouble.

Most of these come from using it against staging and production every day.

Environments you can see

Tag a server local, dev, staging or prod. The accent colour of the whole window changes with it, so you know where you are before you press Run.

Tunnels that start themselves

Give a server a command such as kubectl port-forward. It starts when you connect, restarts if the port answers but lets nothing through, and stops when the app quits.

Your ~/.pgpass works

Servers with no password get one from ~/.pgpass the way psql does, so the config file never has to hold a secret. Passwords you do add go in the macOS Keychain.

Servers as a file

Like ~/.kube/config: one JSON file, with a schema, that you can keep in dotfiles. Or paste postgres:// addresses, one per line, to import them.

Results you can work with

Drag to select a block and copy it. Edit cells in place and delete rows. Open JSON cells in a highlighted viewer. Hide columns, find a column, show dates in a readable form, export.

Rows as a graph

Show a result as a graph of what its rows link to, instead of a flat grid, and pick a card to see its row.

Pooler-safe queries

Each statement goes out in one round trip, so a transaction-mode pooler such as PgBouncer cannot lose a prepared statement between steps.

Tabs, splits, light and dark

One tab per database, kept with its query and results when you switch. Split to put two side by side. Light, dark or follow the system.

Where it fits among the Postgres clients you already know.

Where the others are ahead

DBeaver, DataGrip and TablePlus handle other databases; PgClient never will. DataGrip has deeper refactoring and code analysis. pgAdmin covers server administration such as backup and restore, and PgClient does not. PgClient is young, and has not yet had years of use against odd corners of Postgres.

Where it is built differently

The tools you need during an incident are in the same window as the editor: who is blocking whom, cache hit ratio, a cost-sized plan, and a colour that tells you it is production. The core is a plain Rust crate that knows nothing of windows, so another shell can drive it.

Get started

Running in two minutes.

macOS first. Windows and Linux builds are produced by the release workflow, but passwords are kept in the macOS Keychain only for now.

# a throwaway Postgres to try it against (user, password and database: pgclient)
docker compose -f compose.test.yaml up -d --wait

# build and run the desktop app
npm install && npm --prefix web install
npm run tauri dev

# or install it into /Applications
./install.sh

Add localhost:5435, user pgclient, password pgclient as a server, or list yours in ~/.pgclient/servers.json.
